# 报告结构与质量控制

Phase 3、Phase 4 与 Phase 5，正式报告、Standard / Deep 产物或已有研究的迭代读取本文件。它负责阶段性研究成果、章节审查、用户主导深挖、标准报告骨架、最终整合、机构型行业研究文风和交付检查；不重复证据、Market Sizing 或企业研究方法。

## 分离内部研究与最终报告

内部研究可以使用问题树、证据台账、计算树、框架、审查状态和 Research Delta。Phase 3 可保留必要工作标签、表格和要点；Phase 5 必须转写为正式报告，只呈现读者理解结论所需的证据、机制、限制和含义。不得把 Gate、搜索步骤、审查标签或框架名称机械改成目录。

三种深度共用同一流程：

| 深度 | 研究与输出粒度 |
|---|---|
| Quick | 聚焦核心决策，减少样本与次要模块，仍通过全部真实性和计算检查。 |
| Standard | 建立较完整行业地图，完成章节审查、必要深挖和正式报告。 |
| Deep | 扩大来源、样本、独立验证、反向证据、敏感性与可审计记录。 |

## Standard Report Spine｜标准报告骨架

以下是 Standard / Deep 最终报告的 **Default Non-compressible Spine｜默认不可压缩骨架**，不是参考目录：

0. **执行摘要**
1. **行业概览**
2. **宏观环境与外部约束**
3. **市场分析**
4. **产业链与价值链**
5. **竞争格局**
6. **产品、技术与解决方案**
7. **商业模式与盈利能力**
8. **驱动因素、趋势与风险**
9. **机会与进入判断**【仅在进入者视角适用时】

一级分析功能默认各自独立成章，不因内容相关而自动压缩。一般市场洞察默认保留执行摘要和第一至第八章；只有进入者视角适用时才增加第九章。

一级章名可以按行业改写，但改名不等于合并。例如，第六章可改为“产品结构、门店业态与运营能力”“服务产品、临床能力与诊疗模式”或“产品体系、技术架构与部署模式”，仍须独立承担第六章的分析功能。

合并一级章节是例外，必须同时满足：该功能对本行业确无独立分析价值；单独成章会明显重复；合并不降低可读性；全部分析功能仍被保留；存在可向用户说明的明确理由。不得静默合并。

不适用同样是例外。Phase 5 必须说明模块及理由，不能让它直接消失。宏观环境与外部约束、产品或技术或服务运营体系、商业模式与盈利能力尤其不得无说明省略。

不得以 PEST、五力、SWOT 或自定义主题替代骨架；除非行业特殊到无法归入现有章节，不得新增替代性一级章。二三级标题按行业和问题动态设计，并按以下规则归位：

- 市场定义与发展历程归入行业概览；
- 市场规模、消费者、渠道、区域、价格带和预测归入市场分析；
- 代表企业、竞争路线和行业壁垒归入竞争格局；
- 产品、技术、服务、门店业态、运营与数字化能力归入产品、技术与解决方案；
- 直营、加盟、联营、单店经济性、盈利模式和利润结构归入商业模式与盈利能力；
- 增长驱动、趋势、风险和未来结构判断归入驱动因素、趋势与风险。

## Phase 3｜输出第一版阶段性研究成果

执行 Gate 0—2 已确认的范围与设计，以 **Completeness first** 完成第一轮（Pass 1）。向用户交付一版可独立阅读的阶段性研究成果，使其能够理解行业全貌、主要结论和最值得继续研究的问题。不得只交付研究思路、提纲、资料清单、Evidence Gap 清单或后续待办。

按行业适用性覆盖：

- 行业定义、边界、演变与生命周期；
- 真正重要的外部因素及其作用机制；
- 市场容量、结构、增长、客户、场景与需求；
- 产品、服务、技术或解决方案的差异与演化；
- 供给、产业链、价值链、控制点与利润分布；
- 竞争边界、结构、领先原因、替代品与壁垒；
- 代表性企业、经营路径、商业模式与经济性；
- 驱动因素、趋势、风险与反向证据；
- 结构性机会，以及仅在适用时的进入判断基础。

只研究与问题相关的模块，不要求每部分同等篇幅。生命周期判断不可省略；Standard / Deep 原则上建立基础产业链与价值链认知。框架只有在增加洞察时使用。

第一版可以相对简洁，使用表格、要点、阶段性判断和必要证据标签，但必须包含实质数据、分析解释和初步结论。它不是最终报告，也不得标成最终报告。交付后说明第一轮已完成，接下来进入 Phase 4 的章节审查与选择性深挖。

## Phase 4｜审查并推荐深挖模块

### 内部章节审查

检查每个相关模块的：

- 完整性与是否回答研究目的；
- 证据质量、时效、反向证据和来源—结论匹配；
- 分析深度与机制解释；
- 对最终理解或决策的影响；
- 不确定性、敏感度和重要证据缺口；
- 与其他章节的定义、数据和结论一致性。

内部可以标记：

- `KEEP`：足够支持当前用途；
- `PATCH`：只需补一个明确小缺口；
- `DEEP DIVE`：进一步研究可能实质改变理解或结论；
- `REBUILD`：定义、价值层、测算或核心逻辑需要重构。

这些标签用于组织研究，不默认向用户展示完整审查台账。

### 向用户提出选择

按“决策影响 × 不确定性 × 敏感度 × 进一步研究价值”推荐 **1—4 个**模块。每项只说明：为什么值得深挖、可能改变什么、主要证据缺口是什么。不要把所有薄弱章节都列为建议。

若公开资料继续研究的边际价值很低，可以明确“不建议额外深挖”，但仍询问用户是否要指定一个模块。用户可以选择推荐项、自定模块或结束 Phase 4。

简短示例：

> 当前为 Phase 4。第一轮行业地图已完成。建议优先深挖：①客户付费意愿，因为现有证据主要来自供给方；②价值链利润分布，因为进入环节选择可能因此改变。请先选择一个模块，或告诉我结束 Phase 4。

> 本模块深挖已完成。主要变化：新增一项直接证据，原判断由“证据不足”调整为“有条件支持”，但区域代表性仍是缺口。是否继续深挖其他模块？若不继续，将进入 Phase 5｜最终整合。

### 一次只深挖一个模块

用户选择后，只处理该模块：

1. 明确本轮要解决的问题与边界；
2. 搜集针对性证据和重要反向证据；
3. 必要时重算、补充样本或重构机制；
4. 更新当前研究状态，删除已失效内容；
5. 检查新结果对其他章节、结论和置信度的影响；
6. 输出简短 Research Delta；
7. 询问用户继续选择一个模块，还是结束 Phase 4。

不得自动批量深挖，不预设必须完成多少模块，也不因深挖而把整个研究升级为 Deep。

### 输出 Research Delta｜研究变化摘要

每次深挖后用短段落或紧凑清单说明：

- 本轮新增或强化的关键证据；
- 原判断是保持、加强、削弱还是推翻；
- 对其他章节或最终结论的影响；
- 最大剩余缺口；
- 下一项最高价值问题，如存在。

若新证据没有改变原判断，应如实说明；单纯改写不构成研究变化。Research Delta 位于正式报告之外，不包含隐藏推理链。

### 由用户结束 Phase 4

每轮后明确询问。只有用户表示结束、进入最终报告或确认不再深挖时，才结束 Phase 4。不要以内部停止条件替用户作决定；可以说明继续研究的边际价值已经较低，供用户判断。结束时明确提示：Phase 4 已完成，下一步进入 Phase 5，并将先展示最终报告大纲。

## Phase 5｜确认大纲并最终整合

### 执行两层 Spine Check

目录生成前逐项检查标准模块：

| 模块 | Content Coverage | Structural Coverage |
|---|---|---|
| 行业概览 | 已覆盖 / 遗漏 | 独立成章 / 合并 / 不适用 |
| 宏观环境与外部约束 | 已覆盖 / 遗漏 | 独立成章 / 合并 / 不适用 |
| 市场分析 | 已覆盖 / 遗漏 | 独立成章 / 合并 / 不适用 |
| 产业链与价值链 | 已覆盖 / 遗漏 | 独立成章 / 合并 / 不适用 |
| 竞争格局 | 已覆盖 / 遗漏 | 独立成章 / 合并 / 不适用 |
| 产品、技术或服务运营体系 | 已覆盖 / 遗漏 | 独立成章 / 合并 / 不适用 |
| 商业模式与盈利能力 | 已覆盖 / 遗漏 | 独立成章 / 合并 / 不适用 |
| 驱动因素、趋势与风险 | 已覆盖 / 遗漏 | 独立成章 / 合并 / 不适用 |
| 机会与进入判断 | 已覆盖 / 遗漏 | 独立成章 / 不适用 |

Content Coverage 检查适用内容是否已经研究；Structural Coverage 检查内容是否位于正确的一级结构。若模块经确认确实不适用，Content Coverage 同步记为“不适用”，不视为遗漏。Structural Coverage 默认“独立成章”，“合并”和“不适用”必须满足前述例外条件并记录理由。内容存在但被无理由压缩到其他一级章时，Content Coverage 可通过，Structural Coverage 不通过。

只有两层都通过才能展示目录。真正遗漏的内容先补齐；合并项记录并入位置；不适用项记录原因。同时统一行业定义、范围、地域、时期、客户、价值层、市场规模、企业样本、价格与收入口径、生命周期、竞争、商业模式、风险、机会及结论。矛盾必须解决或解释。

### 展示大纲并等待确认

两层检查通过后，根据 Standard Report Spine 给出拟定一级、二级和必要三级大纲；二三级标题随行业设计，并把 Phase 4 深挖内容放入最合适章节。先展示目录；只有出现合并、不适用、一级标题行业化改名或例外新增时，才在目录后附简短“结构说明”。不要展示完整内部检查表。等待用户确认或调整，未确认不得生成完整报告。

简短示例：

> 当前为 Phase 5。以下目录遵循标准一级骨架。结构说明：第六章根据咖啡行业特点改为“产品结构、门店业态与运营能力”；第九章不适用，因为本研究为一般市场洞察。是否按这个目录整合输出最终报告？

一般市场洞察的目录默认保留执行摘要与第一至第八章。例如咖啡行业仍应分别保留宏观环境、市场分析、价值链、竞争、产品与运营、商业模式、趋势与风险；不得压缩成“市场环境与需求”“产业链与商业经济性”或“竞争与运营”等替代章，除非满足全部合并条件并向用户说明。

### 启用 Structure Lock｜结构锁

用户确认目录后，一级目录即成为本次最终报告的结构约束。除非用户主动要求修改，不得删除、合并、新增替代或重新排序一级章节。正文必须逐章覆盖已确认的一级和二级目录；二三级标题只可作不改变分析功能的轻微措辞调整。

### 生成一份完整报告

大纲确认后，以最新研究状态为唯一基线，重写为连续、口径一致的正式报告：

- 严格遵循已确认目录的一级标题、数量和顺序；
- 使用最新、最强且与命题匹配的证据；
- 删除被推翻的结论并同步所有受影响章节；
- 披露重要假设、代理数据、冲突、局限和证据缺口；
- 对最影响目的的章节给予更高粒度；
- 不拼接 Industry Map、补丁、审查标签或 Research Delta；
- 不输出内部审查表或执行元数据，除非用户明确要求。

### Final Structure QA｜最终结构检查

输出正文前确认：一级章数量、标题和顺序与已确认目录一致；没有静默删除、合并或新增一级章；每章都有实质内容；合并或不适用项与目录确认时的结构说明一致。发现不一致时先修正，再输出报告。

## Iteration Mode｜已有研究的继续与更新

用户要求继续、更新、重算、调整方向或深挖已有研究时，把现有研究作为 Baseline：

1. 确认目标或边界发生了什么变化；
2. 只重开受影响的 Gate：范围变化重开 Gate 0，定义或生命周期变化重开 Gate 1，竞争或测算设计变化重开对应 Gate 2；
3. 聚焦更新受影响模块，不重跑无关内容；
4. 完成影响传导检查，更新所有受影响章节；
5. 输出简短 Research Delta；
6. 需要重新交付正式报告时，仍执行 Phase 5 的骨架覆盖与大纲确认。

用户只要求单模块深挖时，不自动重新生成全报告。公开资料研究已接近饱和不等于结论得到证明；剩余问题依赖访谈、付费数据、实验或经营验证时，应明确区分。

## Institutional Research Prose｜机构型行业研究写作规范

本节强约束 Phase 5 最终报告；Phase 3 可采用更灵活的研究工作稿表达。

### 标题

- 使用名词性、判断性或概括性标题，准确概括研究对象或核心结论；
- 避免问句、口语、媒体化标题和情绪化表达；
- 标题首先服务于报告结构与信息检索，不追求吸引眼球。

例如，把“市场到底有多大？”改为“市场规模持续扩张，增长重心转向消费频次”；把“真正的壁垒是什么？”改为“供应链与运营效率构成规模化经营的核心壁垒”。

### 正文与段落

- 使用正式、客观、克制的研究语言，按**事实与数据 → 分析解释 → 行业影响或判断**展开；
- 每个核心二级章节以有信息密度的完整段落为主，回答 What、Why、How 和 So What；
- 建立章节间因果连接，不堆叠事实后直接跳到强结论；
- 避免口号、营销和网络化表达，避免无证据强因果、模板预告、空泛总结和模型中心叙述；
- 保留不确定性，不把可能、有条件或证据不足升级为确定事实。

### 标点、标签与强调

- 普通概念和分析判断不加中文引号；法定术语、原文引用、行业专有概念或需要明确区分的表达才使用引号；
- 少用“核心判断：”“真正的问题是：”“这意味着：”等冒号式固定句型，以自然段落衔接；
- 避免过度加粗；Fact、Proxy、Calculation、Assumption、Scenario、Inference 和 Evidence Gap 主要用于内部研究与 Phase 3；
- Phase 5 仅在证据性质影响理解、可信度或测算时自然披露，例如“本研究测算显示”“在基准情景下”或“该结果主要用于判断数量级”。

### 列表与表格

- 正文以分析段落为主；列表只用于真正并列的项目、步骤、风险、参数或对比项，不机械罗列大量编号结论；
- 表格只用于市场规模、公司、商业模式、价值链、竞争、参数或风险等结构化比较；
- 表格后用正文解释最重要的差异、原因和影响，不把全部分析塞进表格。

### 执行摘要与最终结论

- 执行摘要结论先行、信息密度高，原则上使用 2—5 个自然段，必要时增加一个小型数据或决策表；不机械输出十条编号结论；
- 执行摘要按适用性覆盖行业阶段、市场规模、结构变化、竞争、商业模式、趋势、风险和条件式进入结论；
- 最终结论不重复执行摘要，而是归纳行业状态、未来核心变量、结构性判断和主要不确定性；
- general market insight 不输出投资、创业或进入建议。

遵循用户指定语言；原始术语或引文可保留原文，分析与报告正文使用目标语言。

## 条件式机会与进入结论

只有进入者视角适用时，说明是否支持进入、置信度、优先客户与产品或服务、进入单元与模式、不建议方向、证据链、成立条件、最强反对理由、风险、缺口和验证行动。

可以使用支持（Support）、有条件支持（Conditional support）、仅建议试点（Pilot only）、证据不足（Insufficient evidence）或不建议（Do not recommend），但必须解释理由。一般市场洞察按 Gate 0 目的形成结论，不强制进入建议。

## 交付前质量检查

所有适用项通过，或局限已经披露并反映在结论强度中，才能交付：

1. **目的与结构：** 回答 Gate 0 的目的；流程、框架和内部标签没有变成目录；Content Coverage 与 Structural Coverage 均已通过。
2. **定义与生命周期：** 边界、纳入项、排除项、邻近市场、阶段证据、反向证据、细分差异和置信度一致。
3. **证据：** 重要事实可追溯到合适且及时的原始来源；引用支持准确命题、地域、时期和强度；冲突与反向证据已处理。
